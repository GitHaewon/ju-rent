## PR-1 · 집계 엔진 + API

### 엔진 (`src/jurent/area.py` 새로 만들기)
| 함수 | 내용 |
|---|---|
| `recent_deals(campus, housing, min_area)` | D-039 범위 거래. 집 종류는 oneroom·officetel·apartment(아파트 정제본, D-034). 기존 정제본·필터 재사용(복사 금지) |
| `budget_search(campus, deposit, monthly, min_area, housing=None, priority, rate_pct)` | 조합별 n, 예산 안 건수·비율(D-040), 환산 월세 중앙값·25/75분위(engine의 converted_monthly·quantiles 재사용), 보증금 중앙값·월세 중앙값(D-042), 면적 중앙값, 쏠림(engine의 dominant_complex 재사용). 추천 목록과 제외 건수(표본 부족·쏠림·25% 미만 각각) 반환. 정렬 D-041 |
| `campus_compare(rate_pct)` | D-043 ①② 계산 |

- 예산 안 판정은 **원 단위 정확 비교**(보증금·월세 원본 값). 정확히 같으면 예산 안
- 비율 경계: 정확히 50%는 "쉽게", 정확히 25%는 "발품"
- 환산율은 D-026(기본 5.0, 2~10%)

### API (`api/main.py`)
| 엔드포인트 | 입력 → 출력 |
|---|---|
| `POST /api/budget` | campus, deposit, monthly, min_area(기본 15, 아파트만 고르면 40), housing(선택: oneroom/officetel/apartment, 없으면 셋 다), priority(cheap/new/large, 기본 cheap), rate_pct(선택) → `budget_search()` 결과 그대로 |
| `GET /api/compare` | rate_pct(선택) → `campus_compare()` 결과 그대로 |
| 검증 | 음수·범위 밖은 422 한국어 메시지 |

## PR-2 · 웹 화면 (디자인은 `docs/design/glass-mockup.html`과 같은 토큰·컴포넌트)

| 항목 | 내용 |
|---|---|
| 상단 탭 | 글래스 세그먼트 "계약 판단 / 예산으로 찾기 / 대학가 비교". 탭 전환 시 내용만 부드럽게 교차(0.25초) |
| 예산으로 찾기 · 입력 패널 | 대학가, 가진 보증금(만 원), 월세 예산(만 원), 최소 면적(슬라이더 + 평), 집 종류 칩(전체/원룸·투룸·빌라/오피스텔/아파트, 기본 전체), 우선순위 세그먼트(저렴하게/새 건물/넓게), 환산율(계약 판단과 공유) |
| 예산으로 찾기 · 결과 | 맨 위 한 줄 요약: "조건에 맞는 조합 N개를 찾았어요". 조합 카드 목록(최대 8개 + 더 보기): 동 이름·집 종류·연식, 가능성 배지("쉽게 구할 수 있어요"/"발품 팔면 가능해요"), "보증금 ○○만 원, 월세 ○○만 원 안팎"(D-042), 예산 안 비율 막대("비슷한 거래 10건 중 N건이 예산 안"), 거래 수. 카드를 누르면 계약 판단 탭으로 그 조건(대학가·집 종류·면적 중앙값·보통 보증금·월세)을 채워 이동 |
| 예산으로 찾기 · 빈 결과 | "이 예산으로는 맞는 조합이 적어요. 월세 예산을 올리거나 최소 면적을 줄여 보세요." + 제외 건수 요약(거래가 적어서 N개, 한 건물에 몰려서 N개, 예산 밖 N개) |
| 대학가 비교 | 두 대학가를 나란히 놓은 글래스 카드: 집 종류 × 면적 구간 표(중앙값, 보통 보증금·월세, 건수, 표본 부족 표시). 아래에 연도별 추이 선 그래프 2개 겹침(2026은 점선·"1~10월"). 숫자는 소수 첫째 자리 |
| 문구 | 해요체, 개발 용어 금지("조합"은 화면에 쓰지 않고 "이런 집" 같은 말로), 관리비 미포함 경고 유지 |
| 모바일 | 한 열, 조합 카드는 가로 스크롤 금지, 입력 패널은 위에서 접기 가능 |
| 모션 | 결과가 바뀌면 카드 목록은 순서 변경 애니메이션(layout), 막대·숫자는 기존 규칙(SPEC-003) |
