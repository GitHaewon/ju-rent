# 전주시 대학가 전월세 실거래 분석: 리빙랩 주제 심층 검증

**검증일:** 2026년 11월 2일

**대상 기간:** 최근 5개 완료 연도인 2021년 1월 1일~2025년 12월 31일(계약일 기준)

**원본:** 국토교통부 실거래가 공개시스템에서 직접 내려받은 완산구·덕진구의 아파트, 연립·다세대, 단독·다가구, 오피스텔 전월세 CSV 40개. 내려받기 당시의 조건과 파일 해시는 [`data/audit/manifest.json`](../data/audit/manifest.json)에 보존했다.

## 결론

**조건부로 추진할 만하다.** 전주시 전체에는 5년간 공개 행 **104,144건**, 전주대 소재 법정동의 대리범위인 효자동2가·3가에는 **19,802건**이 확인됐다. 이 중 소형 월세 비교에 쓸 수 있는 표본은 **5,799건**이다. 따라서 “전주시 실제 자료가 있는가?”에는 답할 수 있다. 다만 이 숫자는 *실거래가 공개시스템에 표시된 행 수*이며, 전체 임대차 계약 수나 정부의 공식 전월세 거래량 통계가 아니다. 캠퍼스 도보권의 정확한 건수도 공개 주소만으로는 낼 수 없다. [국토부 자료제공](https://rt.molit.go.kr/pt/xls/xls.do?mobileAt=), [공개안내](https://rt.molit.go.kr/pt/info/info.do)

주제의 중심은 빈방 검색이나 시세 예측보다 **“학생이 제안받은 보증금·월세를 유사한 과거 계약과 같은 조건으로 비교하고, 근거와 표본 한계를 보여주는 도구”**가 적절하다. 실시간 매물은 제공되지 않으며 사용자가 직접 입력한 조건을 비교한다.

### 전주대학교 주변의 운영상 범위

전주대학교의 공식 주소는 천잠로 303이며 대입정보포털에는 **효자동2가**로 표시된다. 전북특별자치도 도시계획 고시에는 전주대 학교시설 부지가 **효자동3가**에도 걸쳐 있다. 따라서 1차 검증 범위를 **효자동2가·효자동3가**로 정했다. 이 두 법정동 전체를 ‘전주대 생활권의 대리범위’라고 부른다. 캠퍼스 반경 1km, 도보 10분, 학생 거주지와 같은 뜻은 아니다. 유효 표본의 연도별 수는 **2021: 921, 2022: 1,123, 2023: 1,044, 2024: 1,219, 2025: 1,492**건이다. 건물 유형별로는 **단독·다가구 4,936, 오피스텔 455, 아파트 395, 연립·다세대 13**건이다. 2025년만 보면 효자동3가 1,137건, 효자동2가 355건이며, 단독·다가구 1,308, 오피스텔 109, 아파트 70, 연립·다세대 5건이다.

**정확한 캠퍼스 도보권 표본은 미확인이다.** 두 동의 단독·다가구 원본 12,305행 중 12,303행의 지번에 `*` 마스킹이 있다. 단독·다가구가 유효 비교 표본의 85.1%를 차지하므로 개별 건물에 좌표를 찍거나 캠퍼스와의 거리를 계산해 전체 표본으로 제시하면 부정확하다. 지도는 법정동 수준 집계를 기본으로 해야 한다. 국토부도 단독·다가구 지번은 일부만 공개한다고 명시한다. [국토부 단독·다가구 API](https://www.data.go.kr/data/15126472/openapi.do), [실거래가 FAQ](https://rt.molit.go.kr/pt/bbs/faqList.do?mobileAt=&qnaProcessSttusCode=1)

### 데이터 품질과 해석 주의

- CSV 40개의 계약연도와 선택 시군구 불일치는 각각 0행이었다. 두 법정동의 면적, 보증금, 월세금 숫자 결측은 0행이었다. 비교 표본에서 가장 큰 제외 사유는 월세가 아닌 거래와 면적 범위 밖의 거래다.
- `NO`를 제외한 공개 필드가 똑같은 행의 **초과분 5,557행**을 발견했다. 동·호와 고유 계약번호가 없으므로 별개 호실의 동일 조건 계약인지 중복 게시인지 구별할 수 없다. 임의로 삭제하지 않고 공개 행 그대로 집계했다. 이 때문에 수치를 ‘고유 계약 수’라고 표현하지 않는다.
- 2021년 6월부터 임대차 신고 자료가 전월세 공개 대상에 추가됐다. 국토부 FAQ는 소액 계약이 신고·확정일자 자료에서 빠질 수 있다고 경고한다. 따라서 연도별 건수 차이를 곧바로 전주시 임차 수요 증감으로 해석하지 않는다. [국토부 공개안내](https://rt.molit.go.kr/pt/info/info.do), [전월세 FAQ](https://rt.molit.go.kr/pt/bbs/faqList.do?mobileAt=&qnaProcessSttusCode=2)
- 국토부는 공개시스템이 계약일 기준 참고자료이며 외부 공개 시 신고일 기준 공식 통계를 이용하라고 안내한다. 본문의 숫자는 **주제 타당성 검증용 공개 행 수**로만 사용한다. [국토부 자료제공 유의사항](https://rt.molit.go.kr/pt/xls/xls.do?mobileAt=)

## 2. 무료 API 명세와 실제 수집 설계

국토부의 아래 네 API는 공공데이터포털에서 **무료**, 개발·운영단계 **자동승인**, 개발계정 **10,000회/일** 신청 가능으로 표시된다. 페이지의 에러코드 22는 일일 호출량 초과, 23은 초당 호출량 초과다. 초당 정확한 허용 수는 공개 페이지에서 확인되지 않았다. 운영계정은 활용사례 등록 후 증설 신청이 가능하다. 네 API의 형식은 **HTTPS GET → XML**이다. [아파트](https://www.data.go.kr/data/15126474/openapi.do), [연립·다세대](https://www.data.go.kr/data/15126473/openapi.do), [단독·다가구](https://www.data.go.kr/data/15126472/openapi.do), [오피스텔](https://www.data.go.kr/data/15126475/openapi.do)

| 유형 | 공식 API 경로(HTTPS) | 포털 ID |
|---|---|---:|
| 아파트 | `apis.data.go.kr/1613000/RTMSDataSvcAptRent/getRTMSDataSvcAptRent` | 15126474 |
| 연립·다세대 | `apis.data.go.kr/1613000/RTMSDataSvcRHRent/getRTMSDataSvcRHRent` | 15126473 |
| 단독·다가구 | `apis.data.go.kr/1613000/RTMSDataSvcSHRent/getRTMSDataSvcSHRent` | 15126472 |
| 오피스텔 | `apis.data.go.kr/1613000/RTMSDataSvcOffiRent/getRTMSDataSvcOffiRent` | 15126475 |

Swagger에 표시된 **필수 쿼리 변수**는 `LAWD_CD`(법정동 코드 앞 5자리), `DEAL_YMD`(계약년월 6자리, `YYYYMM`), `serviceKey`(공공데이터포털 인증키)다. 예를 들면 `.../getRTMSDataSvcAptRent?LAWD_CD=52111&DEAL_YMD=202501&serviceKey={발급키}`다. 현재 선택 화면의 코드는 **완산구 52111, 덕진구 52113**이다. 2024년 1월 18일 전북특별자치도 출범으로 법정동 코드가 폐지·신설되었으므로, **2021~2023년 API에 현재 코드와 종전 코드(45111·45113) 중 어느 것이 반환되는지는 인증키로 한 달씩 시험하고 CSV와 대조해야 한다.** 이 단계는 아직 수행하지 않았다. [행정안전부 코드 변경](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=106428)

**초기 수집:** 완료 연도 2021~2025의 60개월 × 2개 구 × 4개 건물 유형 = **480회**(API별 120회). 승인된 키로 구·월·유형을 각각 호출하고 XML의 `header.resultCode`, `body.totalCount`, `body.items.item` 및 실제 수신 행 수를 기록한다. 포털의 공개 Swagger는 위 세 입력 변수만 명시하므로 `pageNo`·`numOfRows` 입력을 지원한다고 가정하지 않는다. 응답의 `totalCount`와 실제 item 수가 다르면 완료로 처리하지 않고 기술문서 확인 또는 CSV 대조를 거친다. 요청 간 지연·재시도는 23(초당 제한), 22(일일 제한) 응답에 맞춰 적용한다. 요청 시각, 코드, 응답 해시, 건수를 남겨 재현 가능하게 한다.

**갱신:** 월 1회 최근 3개월을 다시 조회하면 3개월 × 2개 구 × 4종 = **24회/월**이다. 신고 반영·해제로 과거 월이 바뀔 수 있으므로 월별 버전을 보관하고 이전 스냅샷과 차이를 계산한다. 분기마다 전체 5년 재조회는 480회로 개발계정 일일 가능 횟수보다 작지만, 실제 운영에서는 과거 수정 발생률을 보고 주기를 조정한다. 사용자 웹 화면은 저장된 집계 DB를 읽고 실시간으로 국토부 API를 반복 호출하지 않는다.

**검증 상태:** 본 문서의 실제 건수는 인증키 없이 접근 가능한 국토부 공식 **CSV**를 직접 내려받아 계산했다. API의 경로·변수·무료 조건·한도는 공식 Swagger에서 확인했으나, 인증키 발급 및 **실제 API 성공 응답, CSV와의 항목별 일치**는 아직 검증하지 않았다. 따라서 API 수집의 완료 주장이나 API 기반 집계라고 표현하지 않는다.

## 3. 기존 서비스와 남는 문제

| 서비스 | 확인한 현재 기능 | 리빙랩에서 구체적으로 더할 가치 |
|---|---|---|
| 네이버페이 부동산(네이버부동산) | 매물 지도·중개 정보, 단지 시세와 국토부 수급 실거래가를 보여준다. | 학생이 받은 **개별 제안값**을 동일 동·건물유형·면적·보증금·연도·신규 여부의 과거 월세 분포와 비교하고 표본 수, 제외 조건, 원본 기간을 함께 설명한다. 매물 검색 자체는 중복하지 않는다. |
| 직방 | 원룸·오피스텔·빌라 매물 탐색을 제공하고, 2026년에는 **AI중개사**를 원투룸·오피스텔·빌라까지 확장했다. | AI 추천 자체로 차별화를 주장하지 않는다. **전주대 법정동에 한정한 공개 자료의 재현 가능한 비교 근거와 공간·신고 누락 한계**를 보여주는 교육·상담 도구로 좁힌다. |
| 국토부 실거래가 공개시스템 | 공식 계약 내역의 검색·GIS 조회·CSV 다운로드가 가능하다. | 학생의 보증금 예산과 월세 제안값을 입력받아 조건에 맞는 비교집단을 선택하고, 분포와 근거를 이해하기 쉬운 보고서로 제공한다. 원본은 국토부에 연결한다. |

확인 근거: [네이버페이 부동산 도움말](https://help.pay.naver.com/faq/content.help?faqId=17262), [네이버페이 매물지도 안내](https://ads.naver.com/help/faq/1042), [직방 서비스 소개](https://bp.zigbang.com/), [직방 AI중개사 발표](https://company.zigbang.com/newsroom/view?idx=352), [국토부 GIS](https://rt.molit.go.kr/pt/gis/gis.do), [국토부 자료제공](https://rt.molit.go.kr/pt/xls/xls.do?mobileAt=).

이 차별화는 **제품 설계 가설**이다. 각 서비스가 동일한 조건별 비교·근거 설명을 전혀 제공하지 않는다는 전수 검증까지 마친 것은 아니다. 특히 직방에 이미 AI 추천이 있으므로 발표에서 “국내 최초 AI 부동산 추천” 같은 표현은 피해야 한다.

## 4. AI 워크플로우와 실제 화면

**페르소나:** 전주대학교에 입학해 효자동 일대에서 첫 자취방을 찾는 학생. 중개 앱에서 본 방의 월세를 계약 전에 비교하려 하지만, 보증금과 면적이 다른 계약을 어떻게 비교해야 할지 모른다. 전주대 학생상담·주거지원 담당자가 학생에게 비교 근거를 설명하는 보조 화면으로도 쓸 수 있다.

1. **자료 수집 + 출처 기록:** 국토부 CSV로 초기 원본을 확보하고, 키 승인 후 API로 월별 변화를 가져온다. 공개일·계약월·건물유형·지역·원본 해시를 저장한다.
2. **정규화 + 품질검사:** 금액 쉼표와 면적을 숫자로 변환하고, 전북 코드 개편 전후를 정규화한다. 동일 공개 필드 패턴은 표시하되 자동 삭제하지 않는다. 단독·다가구 지번 마스킹과 계약구분 `-`를 유지한다.
3. **비교집단 검색:** 학생이 *법정동, 주택유형, 면적, 보증금, 월세, 계약구분*을 입력하면 먼저 동일 동·유형·최근연도·면적대·보증금대의 유사 계약을 조회한다. 조건과 표본 수를 화면에 공개한다. 표본이 적으면 기간·면적대를 단계적으로 넓히고 무엇을 넓혔는지 보여준다.
4. **결정론적 통계:** 월세의 사분위·중앙값·분포, 연도별 표본 수를 계산한다. 보증금이 크게 다른 계약은 월세만 놓고 ‘저렴/비쌈’을 판정하지 않는다. 보증금 월세 환산은 사용자가 선택한 전환율을 명시할 때만 보조 분석으로 제공한다.
5. **AI 설명:** 언어모델은 계산된 통계와 필터·제외 사유만 전달받아 평이한 한국어로 설명하고, 비교 불가 조건과 확인 질문을 제시한다. 숫자 생성은 계산 모듈이 맡고 설명은 입력 수치와 대조한다. AI 없이도 기본 통계 화면은 동작한다.
6. **결과 검증:** CSV 집계와 API 샘플을 대조하고, 같은 조건에 대해 계산 결과가 재현되는지 확인한다. 학생 인터뷰에서는 “제안 계약의 근거를 이해하는가”를 측정한다. 효과나 정확도 수치는 아직 없다.

**목업 이미지:** [`dashboard_mockup.png`](dashboard_mockup.png). 이 시안에는 2025년 유효 표본 1,492건, 동별 표본 1,137/355건, 건물 유형별 표본과 월세 분포 등 **실제 계산값**을 사용했다. 지도 모양은 설명용 도식이며 실제 경계가 아니다. AI 비교 카드의 `보증금 500 / 월세 40 / 25㎡`는 **가상 사용자 입력**이다. 대응 비교집단은 효자동3가·단독/다가구·2025년 신규·20~30㎡ 미만·보증금 300~700만원의 실제 공개 행 **181건**이고, 월세 25/50/75백분위는 **30/30/40만원**이다. 이 수치는 특정 매물의 적정가나 계약 가능 여부를 보증하지 않는다.

### 웹 화면 구성

- **상단 필터:** 법정동, 건물 유형, 면적, 월세/전세, 계약연도, 신규/갱신/미표시 선택. 필터를 바꾸면 카드와 차트를 같은 기준으로 갱신한다.
- **핵심 지표:** 전주시 전체 공개 행, 캠퍼스 소재 두 법정동의 공개 행, 유효 소형 월세 표본, 선택연도 표본을 구분한다.
- **지역 탐색:** 동 수준 집계만 지도에 표시한다. 개별 건물 점은 제공하지 않는다. 주소가 부족해 도보권을 계산할 수 없음을 표시한다.
- **연도·월세 분포:** 연도별 표본 수와 월세 구간별 빈도를 보여준다. 가격 추세를 보려면 동일 면적·보증금대·주택유형 비교를 적용한다.
- **계약 비교:** 사용자의 입력값과 유사 계약의 표본 수, 중앙값, 중간 50% 범위, 적용한 필터를 함께 보여준다. 비교집단이 빈약하면 답 대신 조건 확대 제안을 한다.
- **품질 패널:** 마스킹, 계약구분 미표시, 신고 누락 가능성, 원본 기준일을 상시 노출한다. 원본 다운로드와 집계 정의를 연결한다.

## 5. 교수 질문에 대한 답과 남은 검증

**“전주에서 몇 건인가?”** 2021~2025년 공개시스템 CSV에서 완산구 50,590, 덕진구 53,554, 합계 104,144행이다. 대학 소재 법정동 효자동2가·3가의 소형 월세 유효 표본은 5,799행이다. 정확한 대학 도보권 계약 수와 미신고 계약 수는 **확인할 수 없다**.

**“왜 기존 앱과 다른가?”** 기존 앱은 매물 검색과 AI 추천까지 제공한다. 이 프로젝트는 전주대 학생이 받은 조건을 공식 계약 분포와 대조하며 **비교 조건·표본 수·주소/신고 한계**를 공개하는 교육적 의사결정 보조 도구다. 상용 앱의 기능 전수 비교와 실제 사용자 수요 인터뷰는 남아 있다.

**“정말 구현 가능한가?”** 초기 공식 CSV 40개를 실제 수집·집계했다. API 명세상 초기 480회, 월 갱신 24회로 무료 개발계정 허용량보다 작다. 다만 인증키로 과거 법정동 코드와 API·CSV의 일치 여부를 확인해야 완전한 자동 수집 가능성을 확정할 수 있다.

**최종 판단:** 집계·대시보드·근거 기반 계약 비교는 학기 프로젝트 범위에 맞는다. “캠퍼스에서 도보 몇 분 내 원룸의 실제 거래가격”, “실시간 공실”, “개별 방의 적정 월세 보증”을 핵심 약속으로 잡으면 공식 데이터의 공간·신고 범위를 넘어선다.
